# 7일 교차 모델 리뷰 실험

## 질문

Claude Code가 구현한 변경을 Codex가 독립 리뷰하면, 추가 시간보다 재작업 감소 효과가 더 큰가?

이 문서는 결과를 보기 전에 고정하는 사전 계획이다. 실험 도중에는 지표, 제외 기준, 배정 순서를 바꾸지 않는다. 예상과 다른 결과도 그대로 공개한다.

## 기간

- 작업 수집: 2026-08-06 00:00부터 2026-08-12 23:59까지 (Asia/Seoul)
- 마지막 작업의 후속 수정 관찰: 완료 후 48시간
- 최소 표본: 완료 작업 8개. 8개 미만이면 결론이 아닌 파일럿으로만 기록한다.

## 대상 작업

다음 조건을 모두 만족하는 작업만 포함한다.

- Claude Code가 주 구현자다.
- 코드 diff가 생기고 완료 여부를 빌드, 테스트, 타입 검사, 화면 확인 중 하나 이상으로 검증할 수 있다.
- 시작 전에 완료 조건을 한 문장 이상 기록할 수 있다.

문서·카피만 바꾸는 작업, 긴급 장애 대응, 실험 시작 전에 이미 구현 중이던 작업은 제외한다. 작업이 어렵다는 이유로 시작 후 제외하지 않는다.

## 배정

기록 CLI가 시작 순서대로 미리 고정된 블록 배정표를 적용한다.

```text
A B B A · B A A B · A B B A
```

- A — 대조군: 현재 쓰는 Claude Code 구현·자체 검증 흐름. 다른 모델의 독립 리뷰는 추가하지 않는다.
- B — 실험군: A와 같은 흐름 뒤, 사람이 최종 판정하기 전에 Codex가 diff를 읽기 전용으로 독립 리뷰한다. 발견 사항을 반영한 뒤 결과를 제출한다.

작업의 크기나 예상 난이도를 본 뒤 그룹을 바꾸지 않는다.

## Codex 리뷰 프롬프트

```text
이 변경을 읽기 전용으로 독립 리뷰해줘. 파일은 수정하지 마.
요청과 완료 조건, base 대비 diff, 관련 테스트를 확인하고 다음만 찾아:
1. 실제 버그나 회귀 가능성
2. 빠진 테스트 또는 검증
3. 보안·데이터 손실 위험
4. 요청 범위를 벗어난 변경
5. 완료 조건을 충족하지 못한 부분

실행 가능한 발견만 심각도·근거와 함께 적고, 없으면 없다고 명시해.
스타일 취향이나 근거 없는 추측은 제외해.
```

## 측정

### 1차 지표

`material_rework`: 에이전트가 완료 후보를 제출한 뒤, 사람이 수락하기 전 기능·정확성·안전성 문제로 다시 수정을 요구했는가.

맞춤법, 순수 스타일 취향, 실험과 무관한 새 요구는 재작업으로 세지 않는다.

### 2차 지표

- `correction_rounds`: 사람이 요구한 실질 수정 라운드 수
- `elapsed_min`: 작업 시작부터 수락 또는 머지까지 경과 시간
- `oversight_min`: 사람이 읽고 판단하고 지시한 대략적인 시간
- `ci_failures`: 최초 완료 후보 이후 실패한 빌드·테스트·CI 횟수
- `review_findings`: B군 Codex 리뷰에서 실제로 반영한 발견 수
- `post_merge_fix_48h`: 완료 후 48시간 안에 같은 원인으로 후속 수정했는가

runmaxing의 대화·도구 호출·비용 지표는 주간 배경 자료로만 사용한다. 개별 작업의 원인 효과를 그 수치만으로 주장하지 않는다.

## 기록 방법

데이터는 `.data/experiments/cross-model-review.json`에 로컬로만 저장되며 Git에 포함되지 않는다.

```bash
npm run experiment:review -- init
npm run experiment:review -- start --title "중립적인 작업명" --done-when "완료 조건"
npm run experiment:review -- finish --id T01 --material-rework no --corrections 0 --ci-failures 0 --oversight-min 8 --review-findings 0 --merged yes
npm run experiment:review -- followup --id T01 --post-merge-fix no
npm run experiment:review -- status
```

제목과 메모에는 고객명, 비밀값, 프롬프트 원문, 소스 코드를 넣지 않는다.

## 판정과 공개

- 그룹별 재작업률과 48시간 후속 수정률을 비교한다.
- 시간은 평균보다 중앙값을 우선한다.
- B군이 재작업을 줄여도 경과 시간이나 감독 시간이 크게 늘면 비용으로 함께 쓴다.
- 작은 표본이므로 통계적 유의성을 주장하지 않는다.
- 결과 글에는 집계치, 실제로 효과가 컸던 작업 유형, 실패한 작업 유형, 재사용 가능한 리뷰 프롬프트를 공개한다.
